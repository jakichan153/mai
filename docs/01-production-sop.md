# 制作SOP（1日2時間 / スマホ中心）

## 前提ツール
| 工程 | ツール | プラン |
|---|---|---|
| 作曲 | Suno AI | Pro |
| 音声結合・整音 | Audacity（PC） / CapCut（スマホ代替） | 無料 |
| ループ映像 | Kling AI | Standard |
| サムネ | Canva | Pro |
| 動画編集・書き出し | CapCut | 無料版 |

> **注意:** Audacityはスマホ非対応。毎日スマホ運用にするなら、音声結合もCapCutのオーディオトラックで完結させる運用に寄せる。PCが使える日にまとめて音声を作る「バッチ方式」を推奨（§3）。

---

## 1. 標準規格（全動画で固定）

| 項目 | 規格 | 理由 |
|---|---|---|
| **尺** | **48〜55分**（目標50分前後） | 1回の作業セッション。過去最大ヒットが46:33 |
| 曲数 | 14〜16曲（1曲3分〜3分30秒） | Sunoの標準生成尺に合う |
| 解像度 | 1920×1080 / 30fps | 長尺の書き出し負荷を抑える |
| ラウドネス | **-16 LUFS 前後** に統一 | 曲間の音量差は離脱の最大要因 |
| 曲間 | クロスフェード 2〜3秒 | 無音を作らない＝止めさせない |
| サムネ | 1280×720 / 「PLAYLIST」帯は必ず維持 | 唯一のブランド資産 |

## 2. 1本あたりの工程（実働 約3.5時間 → 慣れたら2.5時間）

### 工程① 企画・選曲方針（15分）
- シリーズを決める（AFTERNOON / NIGHT DRIVE / MORNING / MIDNIGHT）
- `docs/03-packaging-rules.md` に沿って**先にタイトルとサムネを決める**
- → **重要: 中身より先にパッケージを決める。** 売れる箱を決めてから中身を作る

### 工程② 作曲（60分 / Suno Pro）
- 1シリーズ = 1つの音楽的世界。プロンプトの基礎パーツは固定し、曲ごとに変化をつける
- 14〜16曲生成 → **採用は7割**。妥協した曲を入れると平均視聴時間が落ちる
- 曲名は必ず英語でオリジナルに命名（概要欄のトラックリスト用）

### 工程③ 音声結合・整音（45分 / Audacity or CapCut）
- 曲順設計は `music-curator` の指示に従う（起伏の設計＝離脱防止の本体）
- 全曲を -16 LUFS に正規化 → クロスフェード2〜3秒 → 1本のwav/mp3に書き出し
- **タイムスタンプをメモする**（概要欄に必須）

### 工程④ ループ映像（30分 / Kling AI Standard）
- 5〜10秒のシームレスループを1〜2本生成
- Standardプランはクレジット制限があるため、**1動画1ループ**を基本とする
- プロンプトは `art-director` の管理台帳（`docs/03-packaging-rules.md`）に蓄積

### 工程⑤ サムネ（20分 / Canva Pro）
- テンプレートから複製 → 「PLAYLIST」帯は固定、背景画像とシリーズ名のみ差し替え
- **必ず2案作る**（後でサムネテストに使う）

### 工程⑥ 編集・書き出し（40分 / CapCut）
- ループ映像を尺分リピート配置 → 音声トラック乗せ
- 冒頭5秒に「#番号 SERIES名」のテロップ（登録転換施策）
- 書き出し 1080p / 30fps

### 工程⑦ 投稿設定（20分）
- タイトル・概要欄・タグ: `packager` の出力をそのまま貼る
- **チャプター（タイムスタンプ）を必ず入れる**
- エンドスクリーン + 15分/30分地点に登録カード
- 再生リスト（シリーズ別）に追加
- 固定コメント投稿

## 3. 週次スケジュール案（1日2時間 × 7日 = 14時間）

| 曜日 | 作業 | 時間 |
|---|---|---|
| 月 | **作曲デー**（週3本分をまとめてSuno生成） | 2h |
| 火 | 音声結合 ×1 + **本編①投稿** | 2h |
| 水 | 映像・サムネ ×2 + Shorts ×2 | 2h |
| 木 | 音声結合 ×1 + **本編②投稿** | 2h |
| 金 | Shorts ×2 + 数値記録 | 2h |
| 土 | 音声結合 ×1 + **本編③投稿** | 2h |
| 日 | **振り返り**（`02-analytics-ledger.md` 更新）+ 翌週企画 | 2h |

> 「作曲」「音声」「映像」を曜日でまとめる**バッチ処理**が、スマホ運用で唯一回る形。1本を最初から最後まで通しでやると必ず破綻する。

## 3.5 素材アーカイブ規則【2026-10-12 追加・必須】

> **背景:** AFTERNOON #01 の原曲15曲を Suno のライブラリ整理時に削除し、**曲名も個別音源も復元不能になった。**
> 概要欄にトラックリストを載せていなかったため記録も残っていない。結果、#01 は Shorts の素材として使えなくなった。
> 楽曲は本チャンネルの唯一の資産であり、削除は資産の消滅にあたる。

### 絶対規則
| # | 規則 |
|---|---|
| **R1** | **Suno の原曲は削除しない。** ライブラリが煩雑なら、削除ではなくプレイリスト分けで整理する |
| **R2** | 書き出した個別音源（曲ごとのwav/mp3）を**端末またはクラウドに保存**する。結合後の1本だけを残さない |
| **R3** | 曲名・BPM・生成プロンプトを**公開前に** `docs/videos/<動画名>-music.md` に記録する。記録のない曲は存在しないのと同じ |
| **R4** | **概要欄にトラックリストを必ず載せる。** 万一ローカルの記録を失っても、公開情報として残る |
| **R5** | 結合後のマスター音源（1本につながったファイル）も保存する。個別音源を失っても、ここから切り抜ける |

### 保存先の推奨
```
/audio/<SERIES>_<NN>/
    master.wav          ← 結合後のマスター（R5）
    tracks/01_<曲名>.wav … ← 個別音源（R2）
    tracklist.txt       ← 曲名と開始秒（R3・R4の元）
```

## 4. 品質チェックリスト（投稿前に毎回）

- [ ] 尺は48〜55分か
- [ ] 曲間に無音・音量差がないか（実際に3か所ランダム再生して確認）
- [ ] ループ映像の継ぎ目が目立たないか
- [ ] サムネはスマホサイズ（親指大）でもシリーズ名が読めるか
- [ ] 概要欄に **①コンセプト文（毎回書き下ろし）②全曲タイムスタンプ③AI制作の明記** があるか
- [ ] 冒頭5秒にシリーズ番号テロップが入っているか
- [ ] エンドスクリーン + 中間の登録カードを設定したか
- [ ] 再生リストに追加したか
- [ ] 固定コメント（毎回違う問いかけ）を投稿したか
